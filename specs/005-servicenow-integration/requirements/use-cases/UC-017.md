# Use Case: Employee Data Import from ServiceNow

## Metadata

| Property      | Value                                       |
| ------------- | ------------------------------------------- |
| UC ID         | UC-017                                      |
| User Story    | US-017                                      |
| Feature       | F-005 (gh#6)                                |
| Primary Actor | System Scheduler (BackgroundService)        |
| Scope         | ServiceNow Integration                      |
| Level         | Subfunction                                 |
| Status        | Draft (Phase 2)                             |

## Brief Description

A BackgroundService imports employee vacation balance data from ServiceNow nightly, allowing
employees to see their remaining vacation days when submitting requests. This is informational only
in Phase 1; balance validation may be enforced in Phase 2.

## Stakeholders and Interests

| Stakeholder        | Interest                                                         |
| ------------------ | ---------------------------------------------------------------- |
| Employee           | See remaining vacation days before submitting a request          |
| System             | Accurate balance data without hard enforcement (Phase 1)        |
| ServiceNow         | Single source of truth for vacation entitlements                 |

## Preconditions

1. ServiceNow export (UC-016) has completed for the same night
2. Employee records exist in the vacation system (synced from AD)
3. ServiceNow exposes vacation balance via Table API

## Postconditions (Success Guarantees)

1. Employee.VacationBalance, .VacationUsed, .VacationRemaining updated
2. Employee.BalanceUpdatedAt = now
3. ImportJob record created with counts and status

## Triggers

- Scheduled at 6:00 AM daily (after ServiceNow export window)

---

## Main Success Scenario

| Step | Actor                   | System                                                          |
| ---- | ----------------------- | --------------------------------------------------------------- |
| 1    | PeriodicTimer fires at 6:00 AM |                                                          |
| 2    |                         | System creates ImportJob (Status=InProgress)                    |
| 3    |                         | System queries ServiceNow: GET vacation balances for all employees |
| 4    |                         | For each record: match by Employee.ExternalId                   |
| 5    |                         | System updates Employee balance fields                          |
| 6    |                         | System updates ImportJob counts                                 |
| 7    |                         | System sets ImportJob.Status = Completed                        |

---

## Extensions (Alternative Flows)

### 3a. ServiceNow Unavailable

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 3a.1  |                | API call fails with 503                                       |
| 3a.2  |                | System logs ImportJob.Status = Failed; retains stale balances |
| 3a.3  |                | Admin alert sent                                              |
| 3a.4  |                | Employees see balance with "Last updated: [yesterday]" note   |

### 4a. Employee Not Found Locally

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4a.1  |                | ServiceNow employee ExternalId not in local Employee table    |
| 4a.2  |                | System logs ImportError and skips (AD sync will create them tonight) |

---

## Special Requirements

- **Graceful Degradation**: System continues working if balance data is unavailable
- **Display**: Balance shown with "Last updated" timestamp to set expectations
- **Security**: Read-only access to ServiceNow balance data

## Technology and Data Variations

- **Phase**: Phase 2 implementation; Phase 1 balance display is optional
- **Enforcement**: Balance validation on submit deferred to Phase 2

## Frequency of Occurrence

- Runs: once per day
- Expected records: 500 employee balances
