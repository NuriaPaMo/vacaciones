## Brief Description

A .NET BackgroundService runs nightly at 2:00 AM and synchronizes employee data from Active
Directory via Microsoft Graph API. New employees are created, changed employees updated, and
removed employees soft-deactivated. A SyncJob record captures full results and alerts administrators
on errors.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Scheduler (System) | Complete sync within 30 min; no data loss; idempotent          |
| Administrator      | Accurate employee list for routing; monitoring via admin panel |
| Compliance         | SyncJob and SyncError records for auditability                 |

## Preconditions

1. BackgroundService is running in Azure Container App
2. Managed Identity has Microsoft Graph permissions: User.Read.All, Directory.Read.All
3. No concurrent sync job is already running (distributed lock held)

## Postconditions (Success Guarantees)

1. SyncJob record created with: StartedAt, CompletedAt, Status=Completed, counts
2. Employee table updated: new employees created, changed employees updated, removed deactivated
3. SyncJob.Status = Completed (or PartialSuccess if some records failed)
4. Azure Monitor metric published: sync_duration_ms, employees_processed

## Triggers

- Scheduled at 2:00 AM daily (Azure BackgroundService with PeriodicTimer)

---

## Main Success Scenario

| Step | Actor                   | System                                                          |
| ---- | ----------------------- | --------------------------------------------------------------- |
| 1    | PeriodicTimer fires at 2:00 AM |                                                          |
| 2    |                         | System acquires distributed lock (Redis) to prevent concurrent runs |
| 3    |                         | System creates SyncJob record (Status=InProgress, StartedAt=now)|
| 4    |                         | System calls Graph API: GET /users with $select fields          |
| 5    |                         | System paginates through all users (Graph API nextLink)         |
| 6    |                         | For each user: compare with existing Employee record            |
| 7    |                         | New → INSERT Employee (IsActive=true)                           |
| 8    |                         | Changed → UPDATE Employee fields                                |
| 9    |                         | In DB but not in AD → UPDATE Employee (IsActive=false)          |
| 10   |                         | System updates SyncJob (Created=X, Updated=Y, Deactivated=Z)   |
| 11   |                         | System releases distributed lock                               |
| 12   |                         | System publishes OTel metrics to Azure Monitor                  |

## Extensions (Alternative Flows)

### 4a. Graph API Rate Limit Hit

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4a.1  |                | Graph API returns 429 Too Many Requests with Retry-After header |
| 4a.2  |                | System waits Retry-After seconds, then retries                |
| 4a.3  |                | If 3 retries exhausted: log SyncError, mark SyncJob as Failed  |
| 4a.4  |                | System sends alert email to administrators                    |

### 6a. Individual Record Failure

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 6a.1  |                | Parsing/validation error for one employee record              |
| 6a.2  |                | System creates SyncError record (employee ExternalId, message)|
| 6a.3  |                | System continues with remaining records (batch not aborted)   |

### 2a. Concurrent Lock Held

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 2a.1  |                | System detects lock already held (prior job still running)    |
| 2a.2  |                | System logs warning and exits without creating a new SyncJob  |

### \*a. Error Rate > 5%

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| \*a.1 |                | SyncJob.Errors / SyncJob.TotalProcessed > 5%                  |
| \*a.2 |                | System sends alert email to all administrators                |

## Special Requirements

- **Performance**: Complete within 30 minutes for 500 employees
- **Idempotency**: Running twice produces same final state
- **Security**: Read-only Graph API access; Managed Identity (no stored secrets)
- **Audit**: SyncJob + SyncError records retained for 90 days

## Technology and Data Variations

- **Protocol**: Microsoft Graph SDK for .NET
- **Pagination**: $top=999 with nextLink following
- **Fields Synced**: displayName, mail, department, manager, jobTitle, accountEnabled

## Frequency of Occurrence

- Runs: once per day (nightly)
- Expected duration: 5–10 minutes for 500 employees
