# Use Case: Organizational Hierarchy Sync

| UC ID         | UC-013                                      |
| User Story    | US-013                                      |
| Feature       | F-004 (gh#5)                                |
| Primary Actor | System Scheduler (BackgroundService)        |
| Scope         | Active Directory Integration                |
| Level         | Subfunction                                 |
| Status        | Draft                                       |

## Brief Description

As part of the nightly AD sync, the system derives and updates organizational hierarchy data:
department assignments, manager-employee relationships, and project manager identifications.
Changes in hierarchy are reflected immediately in the vacation system without affecting in-progress
approval workflows.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Scheduler (System) | Accurate hierarchy for correct approval routing                |
| Approval Workflow  | PM and DM must map to correct employees                        |
| Administrator      | Departments and hierarchy visible in admin panel               |

## Preconditions

1. Employee sync (UC-012) has completed for the same sync run
2. AD data includes: department attribute, manager attribute chain

## Postconditions (Success Guarantees)

1. Department records created/updated based on AD department attribute
2. Employee.DepartmentId updated for moved employees
3. Employee.ManagerId updated based on AD manager attribute
4. In-progress approval workflows unaffected by hierarchy changes

## Triggers

- Executed as part of the nightly sync job (UC-012), immediately after employee upsert

---

## Main Success Scenario

| Step | Actor                   | System                                                          |
| ---- | ----------------------- | --------------------------------------------------------------- |
| 1    | Hierarchy sync phase starts (after employee upsert) |                             |
| 2    |                         | System extracts unique department names from synced employees   |
| 3    |                         | System upserts Department records (create new, update existing) |
| 4    |                         | For each employee: resolve manager by AD objectId              |
| 5    |                         | System updates Employee.ManagerId to resolved internal ID      |
| 6    |                         | System updates Employee.DepartmentId from resolved department  |
| 7    |                         | System logs hierarchy changes: new departments, moved employees |

---

## Extensions (Alternative Flows)

### 4a. Manager Not Found in Local Database

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4a.1  |                | Manager's AD objectId not found in Employee table             |
| 4a.2  |                | System logs SyncError: "Manager [ExternalId] not yet synced"  |
| 4a.3  |                | Employee.ManagerId left as previous value (no null overwrite) |

### 6a. Employee Moved to New Department

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 6a.1  |                | Employee.DepartmentId differs from AD department              |
| 6a.2  |                | System updates Employee.DepartmentId                          |
| 6a.3  |                | Pending approval workflows retain original PM/DM approvers   |

### 3a. Empty Department (All Employees Removed)

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 3a.1  |                | No employees remain in a department                           |
| 3a.2  |                | System marks Department.IsActive = false (soft deactivate)    |

---

## Special Requirements

- **Non-breaking**: Hierarchy changes must not invalidate in-progress approvals
- **Audit**: Hierarchy changes logged in SyncJob detail records
- **Security**: Read-only from AD; no writes

## Technology and Data Variations

- **Department Derivation**: From AD `department` attribute (string)
- **Manager Derivation**: From AD `manager` attribute (objectId reference)

## Frequency of Occurrence

- Runs as part of nightly sync (once/day)
- Expected hierarchy changes: < 10/day under normal operations
