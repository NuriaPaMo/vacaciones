# Use Case: Microsoft Teams Notifications

## Metadata

| Property      | Value                                       |
| ------------- | ------------------------------------------- |
| UC ID         | UC-021                                      |
| User Story    | US-021                                      |
| Feature       | F-006 (gh#7)                                |
| Primary Actor | System (Event Handler)                      |
| Scope         | Notifications                               |
| Level         | Subfunction                                 |
| Status        | Draft                                       |

## Brief Description

For every workflow event that triggers an email notification (UC-019), the system also sends a
Microsoft Teams 1:1 chat message to the relevant user via Microsoft Graph API. Teams delivery is
secondary: failures do not affect the workflow or email delivery.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Project Manager    | Receive Teams alerts in the tool they use most                 |
| Employee           | Approval status visible in Teams without checking email        |
| System             | Teams failure must not block primary workflow                  |

## Preconditions

1. Microsoft 365 tenant configured with Graph API access
2. App registration has Chat.Create or Chat.ReadWrite permissions
3. Event has already triggered email notification (UC-019)

## Postconditions (Success Guarantees)

1. Teams message sent with event summary + app link
2. Notification record created: Channel=Teams, Status=Delivered
3. On failure: Notification.Status=Failed; email already sent; workflow unaffected

## Triggers

- Same Service Bus events as UC-019 (secondary handler)

---

## Main Success Scenario

| Step | Actor                   | System                                                          |
| ---- | ----------------------- | --------------------------------------------------------------- |
| 1    | Service Bus message received (e.g., RequestApproved) |                          |
| 2    |                         | System retrieves recipient's Teams user ID from Employee.Email  |
| 3    |                         | System calls Graph API: POST /chats (1:1) or reuse existing chat |
| 4    |                         | System sends message: event summary + "View in App" link        |
| 5    |                         | System creates Notification record (Channel=Teams, Status=Delivered) |

---

## Extensions (Alternative Flows)

### 2a. Employee Has No Teams Account

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 2a.1  |                | Graph API returns 404 for user lookup                         |
| 2a.2  |                | System logs warning; skips Teams; email still delivered       |

### 3a. Graph API Rate Limited

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 3a.1  |                | Graph API returns 429 with Retry-After                        |
| 3a.2  |                | System retries after delay (max 2 retries for Teams only)     |
| 3a.3  |                | If still fails: Notification.Status=Failed; email already sent |

### 3b. Graph API Unavailable

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 3b.1  |                | System catches exception                                      |
| 3b.2  |                | System logs failure; does not retry; email already delivered  |

---

## Special Requirements

- **Non-blocking**: Teams failure must not delay or fail the email notification
- **Adaptive Cards**: Deferred to Phase 2 (plain text messages only in Phase 1)
- **1:1 Chat**: Messages sent to user's 1:1 chat (not team channels)

## Technology and Data Variations

- **Protocol**: Microsoft Graph API v1.0
- **Message Format**: Plain text with markdown link (no adaptive cards in Phase 1)

## Frequency of Occurrence

- Same volume as email notifications (~50/day average)

## Open Issues

- Q-019: Should Teams messages go to a shared channel or only 1:1 chats?
