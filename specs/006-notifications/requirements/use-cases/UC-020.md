# Use Case: Approver Action Links in Email

## Metadata

| Property      | Value                                       |
| ------------- | ------------------------------------------- |
| UC ID         | UC-020                                      |
| User Story    | US-020                                      |
| Feature       | F-006 (gh#7)                                |
| Primary Actor | Project Manager (clicking email link)       |
| Scope         | Notifications                               |
| Level         | Subfunction                                 |
| Status        | Draft                                       |

## Brief Description

Approval notification emails include a "View Request" link that deep-links directly to the
relevant request in the application. The link contains a secure, user-scoped, time-limited token
(7-day expiry) that handles re-authentication if the session has expired.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Project Manager    | One-click navigation from email to approval page               |
| Security           | Links must be user-scoped and time-limited                     |
| Employee           | "View Request" link in status emails reaches correct request   |

## Preconditions

1. A notification email has been sent (UC-019)
2. The link token has not expired (< 7 days old)
3. The link has not been used by a different user

## Postconditions (Success Guarantees)

1. User lands on the correct request detail or approval page
2. If session expired: user re-authenticated and redirected to target page

## Triggers

- Approver or employee clicks "View Request" link in a notification email

---

## Main Success Scenario

| Step | Actor                  | System                                                          |
| ---- | ---------------------- | --------------------------------------------------------------- |
| 1    | PM receives "New Request" notification email |                                   |
| 2    | PM clicks "View Request" button in email |                                       |
| 3    |                        | System receives GET /deep-link?token=<jwt>                      |
| 4    |                        | System validates JWT: signature, expiry, userId claim           |
| 5    |                        | If valid session exists: redirect directly to target URL        |
| 6    |                        | System redirects to: /approvals/{requestId}                     |
| 7    | PM sees the request detail page and can approve/reject |                         |

---

## Extensions (Alternative Flows)

### 4a. JWT Token Expired (> 7 days)

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4a.1  |                | System detects token expired                                  |
| 4a.2  |                | System redirects to login page with error: "This link has expired" |
| 4a.3  | User logs in normally and navigates to Approval Queue         |                    |

### 5a. Session Expired (But Token Valid)

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 5a.1  |                | No active session for user                                    |
| 5a.2  |                | System redirects to Entra ID login; stores target URL in state |
| 5a.3  | User authenticates |                                                           |
| 5a.4  |                | System redirects to original target URL                       |

### 4b. Token Used by Different User (Forwarded Email)

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4b.1  |                | Authenticated user's ID != token userId claim                 |
| 4b.2  |                | System shows error: "This link is not valid for your account" |

---

## Special Requirements

- **Security**: JWT signed with server secret (HMAC-SHA256); user-scoped; 7-day expiry
- **No Auto-Action**: Links only navigate; they do not approve/reject automatically
- **One-Time**: Not enforced (user can click multiple times; each loads the page)

## Technology and Data Variations

- **Token**: JWT with claims: userId, requestId, targetUrl, iat, exp
- **Signing Key**: Stored in Azure Key Vault

## Frequency of Occurrence

- Expected: ~30 link clicks/day (subset of email notifications)
