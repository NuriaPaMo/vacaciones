## Brief Description

A Department Manager reviews vacation requests that have already passed project-level approval and
provides the final approval or rejection. This is the last step before a request is considered
fully approved and eligible for ServiceNow export.

## Stakeholders and Interests

| Stakeholder        | Interest                                                     |
| ------------------ | ------------------------------------------------------------ |
| Department Manager | Maintain department coverage; final authority on all requests |
| Project Manager    | Their approved requests are reviewed and confirmed           |
| Employee           | Final decision on their request                              |
| ServiceNow         | Only fully approved requests are exported                    |

## Preconditions

1. Department Manager is authenticated with the "DepartmentManager" role
2. At least one VacationRequest has CurrentApprovalLevel = Department (project-approved)
3. No active delegation covering DM authority for this period

## Postconditions (Success Guarantees — Approve)

1. ApprovalStep: Level=Department, Status=Approved created
2. VacationRequest.Status = Approved (final)
3. Capacity snapshot updated for affected dates
4. RequestApproved event published → employee notified (F-006)
5. Request becomes eligible for nightly ServiceNow export (F-005)

## Postconditions (Success Guarantees — Reject)

1. ApprovalStep: Level=Department, Status=Rejected, Reason=… created
2. VacationRequest.Status = Rejected (final, overrides project approval)
3. RequestRejected event published → employee notified (F-006)

## Triggers

- DM navigates to "Approval Queue" and sees project-approved requests
- DM receives email notification and clicks action link

## Main Success Scenario — Final Approve

| Step | Actor                   | System                                                        |
| ---- | ----------------------- | ------------------------------------------------------------- |
| 1    | DM navigates to "Approval Queue" |                                                    |
| 2    |                         | System fetches all Department-level pending requests          |
| 3    |                         | System renders queue with capacity impact warnings if applicable |
| 4    | DM reviews request details |                                                         |
| 5    | DM clicks "Final Approve" |                                                          |
| 6    |                         | System creates ApprovalStep (Level=Department, Status=Approved) |
| 7    |                         | System sets VacationRequest.Status = Approved                 |
| 8    |                         | System updates capacity snapshots                             |
| 9    |                         | System publishes RequestApproved event                        |
| 10   |                         | System flags request as pending ServiceNow export             |
| 11   |                         | System shows: "Request fully approved"                        |

## Extensions (Alternative Flows)

### 4a. Request in Over-Capacity Period

| Step  | Actor          | System                                                       |
| ----- | -------------- | ------------------------------------------------------------ |
| 4a.1  |                | System renders a red warning banner: "Warning: This period is at X% capacity (threshold: 70%)" |
| 4a.2  | DM sees warning and decides whether to approve or reject |                        |

### 5a. DM Rejects a Project-Approved Request

| Step  | Actor          | System                                                       |
| ----- | -------------- | ------------------------------------------------------------ |
| 5a.1  | DM clicks "Reject" |                                                          |
| 5a.2  |                | System shows rejection reason textarea (mandatory)           |
| 5a.3  | DM enters reason and confirms |                                                   |
| 5a.4  |                | System creates ApprovalStep (Rejected) and sets request Status = Rejected |
| 5a.5  |                | System publishes RequestRejected event → employee notified   |

### 2a. Escalated Request (PM bypassed)

| Step  | Actor          | System                                                       |
| ----- | -------------- | ------------------------------------------------------------ |
| 2a.1  |                | System renders escalated requests with an "⚠ Escalated" badge |
| 2a.2  | DM reviews and acts directly (no PM step required)                              |

## Special Requirements

- **Performance**: Final approval API < 300ms (P95)
- **Security**: DM can only act on requests from their department
- **Compliance**: Both ApprovalStep records (project + department) are immutable
- **Capacity**: Capacity snapshot must be updated synchronously before returning 200 OK

## Technology and Data Variations

- **Capacity Snapshot**: Updated via direct write to CapacitySnapshot table (Redis cache invalidated)

## Frequency of Occurrence

- Expected: ~10-15 final approvals/DM/week during peak season
- Total: ~200 final approvals/week (summer)
