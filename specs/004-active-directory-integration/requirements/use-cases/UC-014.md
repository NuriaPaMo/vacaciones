## Brief Description

An administrator triggers an immediate AD synchronization from the admin panel, without waiting
for the scheduled nightly run. The system prevents concurrent runs, executes the same sync logic
as the scheduled job, and shows a summary upon completion.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Administrator      | Immediate reflection of org changes (new hires, transfers)     |
| System             | Prevent concurrent sync runs; same logic as scheduled job      |

## Preconditions

1. Administrator is authenticated with "Administrator" role
2. No sync job is currently in progress
3. Last manual sync was more than 1 hour ago (rate limit)

## Postconditions (Success Guarantees)

1. SyncJob created and completed with summary counts
2. Employee and hierarchy data updated in real time
3. SyncJob.Source = "Manual" for audit trail differentiation

## Triggers

- Administrator clicks "Sync Now" on the Integration Health admin page

---

## Main Success Scenario

| Step | Actor             | System                                                          |
| ---- | ----------------- | --------------------------------------------------------------- |
| 1    | Admin navigates to "Admin → Integration Health" |                              |
| 2    |                   | System shows last sync status and "Sync Now" button             |
| 3    | Admin clicks "Sync Now" |                                                           |
| 4    |                   | System checks: no concurrent sync running, rate limit not hit   |
| 5    |                   | System responds 202 Accepted: "Sync started"                    |
| 6    |                   | System executes same logic as UC-012 (async)                    |
| 7    |                   | System updates page in real-time with progress indicator        |
| 8    |                   | Sync completes; system shows summary: Created=X, Updated=Y, Deactivated=Z, Errors=W |

## Extensions (Alternative Flows)

### 4a. Concurrent Sync Already Running

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4a.1  |                | System detects distributed lock held                          |
| 4a.2  |                | System shows: "A sync is already in progress. Please wait."   |
| 4a.3  | Button remains disabled until current sync completes          |                    |

### 4b. Rate Limit: Last Manual Sync < 1 Hour Ago

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4b.1  |                | System detects last SyncJob(Source=Manual) was < 1h ago       |
| 4b.2  |                | System shows: "Manual sync rate limit: 1 per hour. Next allowed at [time]" |

### 8a. Sync Completes with Errors

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 8a.1  |                | Summary shows: "Errors: 3" with a "View Errors" link          |
| 8a.2  | Admin clicks "View Errors" to see SyncError records           |                     |

---

## Special Requirements

- **Security**: Only "Administrator" role can trigger manual sync
- **Async**: Response is immediate (202); progress shown via polling or SSE
- **Idempotency**: Manual sync produces same result as scheduled sync

## Technology and Data Variations

- **Response**: 202 Accepted with SyncJob ID for status polling
- **Progress**: Frontend polls GET /api/admin/sync/{jobId} every 5 seconds

## Frequency of Occurrence

- Expected: 1–2 manual syncs/week (after org changes)
- Max: 24/day (rate limit)
