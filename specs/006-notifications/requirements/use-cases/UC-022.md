## Brief Description

After each approval or cancellation, the system evaluates capacity for affected periods. When a
period crosses a threshold for the first time (Warning 65-70% or Critical >70%), the system sends
targeted alerts to relevant managers. Duplicate alerts for the same threshold crossing are
suppressed.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Department Manager | Proactive warning before a period becomes critically over-subscribed |
| Project Manager    | Aware of capacity issues in their project                     |
| System             | Alert exactly once per threshold crossing (no spam)           |

## Preconditions

1. A VacationRequest has just been Approved or Cancelled
2. Capacity snapshot has been updated for affected dates
3. ThresholdConfig exists for the department

## Postconditions (Success Guarantees — Critical Alert)

1. CapacityAlert record created (prevents duplicate alerts)
2. Email sent to DM
3. Teams message sent to DM and all affected PMs

## Postconditions (Success Guarantees — Warning Alert)

1. CapacityAlert record created
2. Email sent to DM only (no Teams)

## Triggers

- CapacityThresholdCrossed event published after capacity recalculation

---

## Main Success Scenario — Critical Alert (>70%)

| Step | Actor                   | System                                                          |
| ---- | ----------------------- | --------------------------------------------------------------- |
| 1    | Approval triggers capacity recalculation                                         |
| 2    |                         | System detects period X crosses Critical threshold (>70%)       |
| 3    |                         | System checks: no existing CapacityAlert for period X at Critical level |
| 4    |                         | System creates CapacityAlert record (prevents duplicate)        |
| 5    |                         | System sends email to DM: "Critical: Week of [date] at 75% capacity" |
| 6    |                         | System sends Teams message to DM and all PMs with employees on vacation that week |
| 7    |                         | Alert includes: affected dates, current %, threshold, link to heat map |

### Warning Alert Scenario (65–70%)

| Step | Actor                   | System                                                          |
| ---- | ----------------------- | --------------------------------------------------------------- |
| 2    |                         | System detects period X crosses Warning threshold (65–70%)      |
| 5    |                         | System sends email to DM only                                   |
| 6    |                         | (No Teams message for Warning level)                            |

## Extensions (Alternative Flows)

### 3a. Alert Already Sent for This Period and Threshold

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 3a.1  |                | System finds existing CapacityAlert for same period + threshold |
| 3a.2  |                | System suppresses duplicate; no notification sent             |

### 1a. Cancellation Drops Period Below Threshold

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 1a.1  |                | Capacity drops below Critical after a cancellation            |
| 1a.2  |                | System clears CapacityAlert for that period/threshold (allows re-alert if it crosses again) |

---

## Special Requirements

- **Deduplication**: One alert per period + threshold crossing (CapacityAlert record as gate)
- **Timing**: Alert sent within 5 minutes of capacity crossing
- **Performance**: Capacity check after approval < 500ms

## Technology and Data Variations

- **Threshold Source**: ThresholdConfig per department (configurable in F-007)
- **Alert Channel**: Warning = email only; Critical = email + Teams

## Frequency of Occurrence

- Expected: 2–5 capacity alerts/month (summer)
- Peak: July (summer peak) — ~10 alerts
