## Brief Description

The notification service listens to Azure Service Bus events published by the workflow (request
submitted, approved, rejected, cancelled, escalated) and sends branded HTML email notifications
to the relevant recipients within 5 minutes of the triggering event.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Employee           | Instant email when their request status changes                |
| Project Manager    | Email when a new request needs their attention                 |
| Department Manager | Email when escalation or over-capacity events occur            |
| Administrator      | Template management; delivery failure visibility               |

## Preconditions

1. Notification BackgroundService is running
2. SMTP server accessible and configured
3. NotificationTemplate records exist for all event types
4. Service Bus has unprocessed notification messages

## Postconditions (Success Guarantees)

1. Email delivered to recipient within 5 minutes
2. Notification record created: Type, Channel=Email, Status=Delivered, SentAt
3. On failure: Notification.Status=Failed with ErrorMessage; retry queued

## Triggers

- Service Bus message received for: RequestSubmitted, RequestApproved, RequestRejected,
  RequestCancelled, EscalationTriggered, CapacityThresholdExceeded

---

## Main Success Scenario

| Step | Actor                   | System                                                          |
| ---- | ----------------------- | --------------------------------------------------------------- |
| 1    | Workflow publishes RequestApproved event to Service Bus |                        |
| 2    |                         | Notification handler picks up message                           |
| 3    |                         | System determines recipient(s) from event payload               |
| 4    |                         | System fetches NotificationTemplate for event type + channel    |
| 5    |                         | System merges template with event data (employee name, dates)   |
| 6    |                         | System sends HTML email via SMTP                                |
| 7    |                         | System creates Notification record (Status=Delivered)           |
| 8    |                         | Service Bus message acknowledged                                |

---

## Extensions (Alternative Flows)

### 6a. SMTP Delivery Fails

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 6a.1  |                | SMTP call fails                                               |
| 6a.2  |                | System creates Notification (Status=Failed, ErrorMessage)     |
| 6a.3  |                | System retries: 3 attempts (backoff: 30s, 5min, 30min)        |
| 6a.4  |                | After 3 failures: message dead-lettered; admin alert triggered |

### 4a. Template Not Found

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4a.1  |                | No NotificationTemplate for this event type                   |
| 4a.2  |                | System logs error; skips email; does not fail the workflow     |

---

## Special Requirements

- **Performance**: Email sent within 5 minutes of triggering event
- **Security**: Email body contains no sensitive PII beyond name, dates, status
- **GDPR**: No consent required (operational notifications)
- **Template Security**: No HTML injection from user-provided content (sanitize notes field)

## Technology and Data Variations

- **SMTP**: TLS connection to corporate mail relay
- **HTML Templates**: Stored in NotificationTemplate table; Handlebars or Razor syntax

## Frequency of Occurrence

- Expected: ~50 emails/day average; ~200/day peak (summer approvals)
