## Brief Description

An administrator searches for users, views their roles and active delegations, assigns or changes
roles, deactivates users, and manages delegation assignments. Role changes take effect immediately
and are fully audited.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Administrator      | Maintain accurate roles; handle leavers and joiners            |
| Compliance         | Role changes audited; only authorized users hold approver roles |
| Project Manager    | Role correctly reflects approval authority                     |

## Preconditions

1. User is authenticated with Administrator role
2. Employee records exist (synced from AD)

## Postconditions (Success Guarantees — Role Change)

1. Employee.Role updated to new value
2. AuditEntry created: before role, after role, actor, timestamp
3. New role takes effect on next authentication (JWT refresh)

## Postconditions (Success Guarantees — Deactivation)

1. Employee.IsActive = false
2. All active sessions invalidated
3. Active delegations revoked for deactivated user
4. AuditEntry created

## Triggers

- Administrator navigates to "Admin → User Management"

## Special Requirements

- **Security**: Only Administrator role can manage users
- **Real-time**: Deactivation revokes sessions immediately
- **Audit**: All role changes and deactivations audited
- **Safety**: Cannot remove last administrator

## Technology and Data Variations

- **Session Invalidation**: Revoke Entra ID refresh tokens via Graph API on deactivation
- **Role Propagation**: New roles take effect on next JWT token refresh (max 1h delay)

## Frequency of Occurrence

- Expected: ~5 role changes/month; ~2 deactivations/month (leavers)
