## Brief Description

An administrator configures system parameters through the admin panel: capacity thresholds,
escalation timeframes, email/Teams notification templates, batch job schedules, and
department-specific policy overrides. All changes take effect immediately and are audited.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Administrator      | Self-service configuration without developer intervention      |
| Department Manager | Department-specific thresholds respected                       |
| Compliance         | Configuration changes audited with before/after values         |

## Preconditions

1. User is authenticated with Administrator role
2. SystemConfiguration table exists with default values

## Postconditions (Success Guarantees)

1. SystemConfiguration record updated with new value
2. AuditEntry created with: before value, after value, actor, timestamp
3. Configuration takes effect immediately (no restart required)

## Triggers

- Administrator navigates to "Admin → Configuration"

---

## Main Success Scenario — Change Capacity Threshold

| Step | Actor             | System                                                          |
| ---- | ----------------- | --------------------------------------------------------------- |
| 1    | Admin navigates to "Admin → Configuration" |                                     |
| 2    |                   | System renders configuration sections: Capacity, Escalation, Notifications, Integrations |
| 3    | Admin expands "Capacity Thresholds" section |                                    |
| 4    |                   | System shows current values: Warning=65%, Critical=70%          |
| 5    | Admin changes Critical threshold to 75% |                                       |
| 6    | Admin clicks "Save" |                                                            |
| 7    |                   | System validates: 1 ≤ value ≤ 100; Warning < Critical          |
| 8    |                   | System updates SystemConfiguration record                       |
| 9    |                   | System creates AuditEntry (before: 70%, after: 75%)             |
| 10   |                   | System shows success: "Configuration saved. New threshold applies immediately." |
| 11   |                   | CapacitySnapshot re-evaluation happens at next calculation     |

## Extensions (Alternative Flows)

### 7a. Validation Failure

| Step  | Actor          | System                                                       |
| ----- | -------------- | ------------------------------------------------------------ |
| 7a.1  | Admin enters 105% |                                                         |
| 7a.2  |                | System shows inline error: "Threshold must be between 1 and 100" |

### 7b. Warning ≥ Critical

| Step  | Actor          | System                                                       |
| ----- | -------------- | ------------------------------------------------------------ |
| 7b.1  | Admin sets Warning=80%, Critical=75% |                                    |
| 7b.2  |                | System shows error: "Warning threshold must be less than Critical threshold" |

### Department-Specific Override

| Step | Actor             | System                                                       |
| ---- | ----------------- | ------------------------------------------------------------ |
| 3    | Admin selects specific department from dropdown |                         |
| 4    |                   | System shows department-specific overrides (or "inherits global") |
| 5    | Admin sets department Critical threshold to 80% |                         |
| 6    |                   | System creates department-scoped SystemConfiguration         |
| 7    |                   | Department uses 80%; others use global 70%                   |

## Special Requirements

- **Real-time**: Configuration changes take effect immediately
- **Validation**: Input validation on all configuration fields
- **Audit**: All changes audited (before/after in AuditEntry)
- **Security**: Only Administrator role

## Technology and Data Variations

- **Storage**: SystemConfiguration table (Key, Value, Scope, DepartmentId)
- **Cache**: Configuration cached in IMemoryCache (L1); invalidated on save

## Frequency of Occurrence

- Expected: ~2 configuration changes/month
- Peak: Start of season (threshold adjustments for summer/winter)
