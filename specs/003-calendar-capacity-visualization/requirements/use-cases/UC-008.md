## Brief Description

A Project Manager or Department Manager views a visual calendar showing their team's vacation
schedule. The calendar is color-coded by request status and supports weekly/monthly views, custom
date ranges, and filtering by team or project.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Project Manager    | Identify coverage gaps before approving new requests           |
| Department Manager | Oversee department-wide vacation distribution                  |
| Employee           | See teammates' approved vacations when planning own request    |

## Preconditions

1. User is authenticated with PM, DM, or Employee role
2. VacationRequest records exist with status Pending or Approved
3. Organizational hierarchy loaded from AD (F-004)

## Postconditions (Success Guarantees)

1. Calendar rendered with all relevant requests displayed
2. Color coding correctly reflects current request statuses
3. Render time < 1 second for 50 employees / 1 month

## Triggers

- User clicks "Team Calendar" in the navigation menu
- User clicks "View Calendar" from the dashboard

---

## Main Success Scenario

| Step | Actor             | System                                                          |
| ---- | ----------------- | --------------------------------------------------------------- |
| 1    | PM navigates to "Team Calendar" |                                                  |
| 2    |                   | System defaults to current week view for PM's project           |
| 3    |                   | System fetches requests for all project members for visible range |
| 4    |                   | System renders calendar: employees on rows, dates on columns    |
| 5    |                   | Approved vacations shown in green; Pending in yellow; Rejected in grey |
| 6    | PM reviews the calendar |                                                         |
| 7    | PM switches to monthly view |                                                       |
| 8    |                   | System re-fetches and renders monthly calendar (< 1 second)     |
| 9    | PM filters by a specific team |                                                     |
| 10   |                   | System re-renders showing only the selected team's members      |

## Extensions (Alternative Flows)

### 2a. DM Views Department Calendar

| ----- | -------------- | ------------------------------------------------------------ |

### 2b. Employee Views Team Calendar

| Step  | Actor          | System                                                       |
| ----- | -------------- | ------------------------------------------------------------ |
| 2b.1  |                | System shows only Approved vacations (not Pending) for other employees |
| 2b.2  |                | Employee's own Pending requests are visible only to themselves |

### 7a. Custom Date Range Selected

| Step  | Actor                     | System                                         |
| ----- | ------------------------- | ---------------------------------------------- |

### \*a. No Requests in Visible Range

| Step  | Actor          | System                                                       |
| ----- | -------------- | ------------------------------------------------------------ |

## Special Requirements

- **Performance**: Render < 1 second for 50 employees, 1-month view
- **Security**: Employees see only their team's approved vacations
- **Accessibility**: Calendar must be navigable without a mouse (WCAG 2.1 AA)

## Technology and Data Variations

- **Caching**: Capacity data pre-computed in Redis; calendar reads from cache
- **Timezone**: All dates display in user's local timezone

## Frequency of Occurrence

- Expected: ~10 calendar views/manager/day = ~1,000 views/day (500 employees)
