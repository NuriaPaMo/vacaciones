## Brief Description

An administrator monitors the ServiceNow export health from the admin panel and manually retries
failed export records. The system displays last export status, 30-day history, and details of
failed records including error messages and retry counts.

## Stakeholders and Interests

| Stakeholder        | Interest                                                       |
| ------------------ | -------------------------------------------------------------- |
| Administrator      | Detect and recover from export failures quickly                |
| ServiceNow         | All approved vacations eventually arrive in ServiceNow         |

## Preconditions

1. Administrator is authenticated
2. At least one ExportJob record exists

## Postconditions (Success Guarantees — Manual Retry)

1. Failed ExportRecord re-processed against ServiceNow API
2. On success: ExportRecord.Status = Exported, retry counter reset
3. On failure: ExportRecord.RetryCount incremented, error message updated

## Triggers

- Administrator navigates to "Admin → ServiceNow Integration"
- System sends automatic alert email on > 5% error rate

---

## Main Success Scenario — View Health

| Step | Actor             | System                                                          |
| ---- | ----------------- | --------------------------------------------------------------- |
| 1    | Admin navigates to "ServiceNow Integration" |                                   |
| 2    |                   | System fetches last ExportJob                                   |
| 3    |                   | System renders: Status, Timestamp, Exported/Updated/Deleted/Errors |
| 4    |                   | System renders 30-day history table                             |
| 5    | Admin clicks on a failed job |                                                      |
| 6    |                   | System fetches ExportRecord failures for that job               |
| 7    |                   | System renders: employee name, dates, error message, retry count |

### Manual Retry Scenario

| Step | Actor             | System                                                          |
| ---- | ----------------- | --------------------------------------------------------------- |
| 1    | Admin clicks "Retry" on a failed ExportRecord |                                  |
| 2    |                   | System publishes RetryExport command to Service Bus             |
| 3    |                   | System responds: "Retry queued"                                 |
| 4    |                   | Background handler retries the ServiceNow API call              |
| 5    |                   | On success: ExportRecord updated to Exported                    |
| 6    |                   | Admin page refreshes to show updated status                     |

## Extensions (Alternative Flows)

### 4a. Retry Also Fails

| Step  | Actor          | System                                                        |
| ----- | -------------- | ------------------------------------------------------------- |
| 4a.1  |                | ServiceNow API call fails again                               |
| 4a.2  |                | ExportRecord.RetryCount incremented, ErrorMessage updated      |
| 4a.3  |                | Admin sees updated error; can contact ServiceNow support       |

## Special Requirements

- **Security**: Only Administrator role can view and retry exports
- **Retention**: ExportJob history retained for 90 days
- **Performance**: Health page load < 2 seconds

## Technology and Data Variations

- **Retry**: Async via Azure Service Bus (fire-and-forget with status polling)

## Frequency of Occurrence

- Expected: Admins check 1–2 times/week; manual retries rare (0–5/month)
